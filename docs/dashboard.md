# Dashboardの使い方

`RaceTime Integration`パネルはOverview / Mappings / Settingsの3つのタブで構成されます。このページはレースの監視から設定までの操作の流れに沿って説明します。

## レースを監視する

1. `Overview`タブを開きます。
2. 左側の「URLで監視を追加」にRaceTimeのレースURLを入力します。
3. 「監視を追加」を押します。

同じURLをすでに監視している場合は、新しく監視を開始せず、そのレースを選択します。監視を開始できたレースは自動的に選択されます。失敗した場合は、右側の上部にエラーが表示されます。

「監視中のレース」の各項目にはレースID（未取得のときはURL）とタイマー、`RaceTime: {status}`、`Connection: {connection} · E{participantsRevision}`が表示されます。項目をクリックするとレースを選択します。タイマーは選択していないレースも更新されます。

## 監視中に確認する

レースを選択すると、右側にレースタイマー、レース情報、イベントログ、マッピング、参加者、Leaderboardが表示されます。

### レースタイマー

レースタイマーは、RaceTimeから取得した時刻と現在時刻から計算します。状態に応じて、表示とラベルが変わります。

| RaceTime状態 | 表示 |
| --- | --- |
| `open` / `invitational` | 「開始待ち」。`startDelay`に基づく負の時間（開始までの残り）を固定表示する。カウントダウンはしない |
| `pending` | 「カウントダウン」。開始予定時刻までカウントダウンし、0に達したあとは「進行中」として経過時間を表示する |
| `in_progress` | 「進行中」。開始時刻からの経過時間を表示する |
| `finished` | 「終了」。開始時刻から終了時刻までの経過時間を固定表示する |
| `cancelled` | 「中止」。開始前の中止では数値を表示せず、開始後の中止では中止までの経過時間を表示する |
| `partitioned` | タイマーを表示しない |
| 必要な時間情報がない | 「未取得」 |

表示精度は、選択中のレース詳細では10分の1秒まで、監視一覧では秒単位です。更新周期は表示精度とは別で、詳細は約0.1秒ごと、一覧は約1秒ごとに再計算します。RaceTimeへの接続が切れている間は、最新の状態と一致していない可能性があります。

### レース情報

作成日時、開始日時、終了日時、中止日時、カウントダウン、制限時間、説明、記録関連の状態、完走人数、DNF / DQ人数、制限時間到達時の処理を表示します。日時は利用環境のローカルタイムゾーンで、未設定は「未設定」と表示します。

### イベントログ

監視中に受信したレース状態変化イベントを、受信時刻・イベント名・詳細の順で表示します。イベントの種類は[公開API](../packages/racetime-protocol/README.md#レース状態変化イベント)を参照してください。

- 表示するのは選択中のレースのイベントだけです。
- 保持件数はレースURLごとに最大100件で、古いものから破棄します。
- 履歴はDashboardを開いている間だけ保持し、消去用のボタンはありません。

## 参加者を紐付ける

RaceTimeの参加者はPlayer ManagerのプレイヤーとRaceTimeアカウントを通じて結び付けられます。解決できた参加者はPlayer Managerの表示名と、そのプレイヤーのSpeedrun.comアカウントから取得したPBを表示します。

- 未解決（unresolved）の参加者には「登録・紐付け」ボタンがあります。押すとPlayer Managerの登録画面を新しいタブで開きます。
- 解決済みの参加者には「編集 ↗」リンクがあり、Player Managerの編集画面を開きます。
- PBを取り直すには「PBを再取得」を押します。

PBはマッピングを登録している場合だけ取得できます。PB列の状態（未取得・記録なし・未連携・古いデータなど）は、取得状況に応じて表示されます。

## Speedrun.comの記録を表示する

選択中のレースにマッピングが登録されていると、「Speedrun.com マッピング」に要約が表示され、その下に条件別Leaderboardが表示されます。

- マッピングが未登録の場合は「未登録」と表示します。先に[マッピング](mappings.md)を登録してください。
- 「編集」でその場でマッピングを編集できます。編集操作はMappingsタブと同じです。
- Leaderboardの「再取得」で最新の記録を取得します。

## 監視を停止する

レース詳細の「監視を停止」を押すと、確認ダイアログが開きます。実行すると、そのレースの監視セッション全体を停止します。

この操作は共有監視セッション全体に適用されます。ほかのバンドルが保持している監視も解除されますが、RaceTime上のレース自体は変更されません。

## Mappingsタブ

MappingsはRaceTimeとSpeedrun.comのマッピングを編集する画面です。左側にRaceTimeゲームの一覧と検索、右側に選択したゲームの登録済みSRCゲームとGoal一覧を表示します。

### Game Mapping

1. 「＋ 新規」で新しいGame Mappingを作成します。
2. `RaceTime category slug（一意キー）`と`RaceTime category name（表示用）`を入力します。slugとSRCゲームIDの組が一意キーで、保存後はどちらも変更できません。表示名は更新できます。
3. SRCゲームを「Speedrun.com ゲーム（手動選択）」で検索して選びます。自動マッピングや候補の提案は行いません。
4. 「Game Mappingを保存」で保存します。削除は「削除」から行います。

同じRaceTimeゲームへ別のSRCゲームを登録するには「SRCゲームを追加」を使います。検索結果に同じSRCゲームがあっても重複登録はできません。「登録済みSRCゲーム」から個別に選んで編集・削除できます。

削除対象のSRCゲームを参照するCategory Mappingがある場合は削除できません。他のSRCゲームを参照するGoalは削除を妨げません。

### Category Mapping

1. ゲームを選択した状態で、Category Mappingsの「＋ 新規 Goal」から作成します。
2. `RaceTime Goal`を入力し、`SRC Game（必須）`で登録済みSRCゲームを選んでから`SRC Category（必須）`を指定します。
3. per-levelカテゴリでは`Level`、必要に応じて`Platform`、`Region`、`Emulator`、`Timing Method`を指定します。
4. Variablesはカテゴリの定義に従って値を選びます。「Any（すべて）」を選べるVariableでは、定義済みのすべての値を対象にできます。指定条件の詳細は[マッピング](mappings.md)を参照してください。
5. 「Category Mappingを保存」で保存します。

同じSRCカテゴリを指すGoalでも、別名は個別の行として表示します。SRCゲームを変更すると、旧ゲームに依存したカテゴリ・Level・Variableなどの選択はクリアされます。Revertで保存済みのゲームと条件へ戻せます。

Game Mappingの保存後は編集画面を開いたままにします。Category Mappingの保存後は、Game Mappingに未保存変更がなければ編集画面を閉じます。保存成功の通知は閉じたあとも残ります。

Overviewの編集画面でも同じSRCゲーム一覧とゲーム選択を使います。Goalは監視中のレースの値を使用します。

### 競合の解決

マッピングが別の場所で更新されていると、保存時に競合が検出されます。「最新状態を採用」か「最新状態から再編集」を選んで解消します。解決するまで保存はできません。「最新状態から再編集」では、以前の入力内容が比較用に残ります。

### Variablesの検証

保存前に、Variablesが現在のSpeedrun.com定義と整合するかを確認します。`Any`が使えなくなったVariableは値を選び直すまで、Speedrun.comから削除されたVariableは下書きから削除するまで、保存できません。PB区分を特定するVariableが未選択の場合も保存できません。

## Settingsタブ

SettingsはSpreadsheetの接続とRaceTimeの接続先を設定する画面です。

### Spreadsheet

- `Spreadsheet URL または ID`、`GameMappings シート名`、`CategoryMappings シート名`を入力します。
- `Any展開の最大件数`と`リーダーボード取得順位数`（いずれも初期値20）は1以上の整数で入力します。
- 「保存」は入力内容を永続設定へ保存します。接続先を変更した場合は、両シートを検証できた場合だけ切り替えます。
- 「Spreadsheetを初期化」は、入力中のSpreadsheetに両シートを準備します。この操作は設定を保存しません。
- 接続状態バッジは保存時に両シートを検証できた場合だけ「利用可能」になります。

初期化と保存の順序は[導入と初期設定](getting-started.md)を参照してください。Google認証情報の入力は不要です（ADCを使用します）。

### RaceTime接続設定

監視できるRaceTimeの接続先（`allowedRaceOrigins`）を編集します。初期値は`https://racetime.gg`です。HTTPSのOriginと、`localhost`などのループバックHTTPを登録できます。追加・削除は「保存」で確定します。許可リストから外した接続先の監視は停止します。

## 誤解しやすい動作

- 「監視を停止」はそのレースの共有監視セッション全体を止めます。ほかのバンドルの監視も解除されます。
- イベントログは永続化されません。Overviewを閉じると失われます。
- 監視一覧のタイマーは選択していないレースも常に動作します。
- レース情報の更新や削除が外部で起きた場合、未保存のマッピング編集があると勝手に切り替わらず、確認が表示されます。
- 保存や再読込の実行中は、タブの切り替えとフォームの操作が禁止されます。
